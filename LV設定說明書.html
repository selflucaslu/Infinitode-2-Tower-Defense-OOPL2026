關卡設定開發說明書

本文件旨在指導開發人員如何於 C++ 專案中新增、修改及優化塔防遊戲關卡設定。 關卡的配置資料儲存於 LevelConfig.cpp， 並由頭文件 LevelConfig.hpp 定義相關的資料結構。

核心結構解析

關卡設定採用三層式的巢狀結構：LevelConfig (關卡) ➔ WaveConfig (波次) ➔ SpawnGroup (刷怪組)。以下為其詳細的變數屬性說明與設計準則。

1. LevelConfig (關卡配置)

定義單一關卡的全域基本屬性，如關卡編號、地圖檔案路徑、生命值與初始資金等。

屬性變數 (型態) 預設值 校驗規則 / 限制條件 功能說明
levelNumber (int) 1 必須大於 0 且在全域中唯一 關卡 ID，UI 上顯示與讀取識別用。
mapPath (string) "" 路徑不可為空，且 CSV 檔案必須存在 對應的 CSV 地圖檔案路徑，例如 "assets/maps/map_01.csv"。
baseHp (int) 20 必須大於 0 本關玩家基地生命值 (抵達終點的敵人扣減生命值)。
startingGold (int) 150 無特別限制 (一般大於 0) 開局時玩家所擁有的初始金幣。
waves (vector) 空 陣列不可為空 該關卡所包含的所有波次列表。

2. WaveConfig (波次配置)

定義每個獨立波次的屬性，控制波次倒數時間、獎勵金幣，以及其內包含的多個敵人刷怪組。

屬性變數 (型態) 預設值 校驗規則 / 限制條件 功能說明
waveNumber (int) 1 必須大於 0 波次編號 (以 1 開始，作為 UI 上顯示的序號)。
isBossWave (bool) false 無 是否為 Boss 波次。可用於觸發特殊的 Boss 關卡警告與 UI 顯示。
prepTime (float) 3.0F 必須大於或等於 0.0F 波次開始前的準備倒數時間（單位：秒）。倒數完畢後開始出怪。
clearRewardGold (int) 0 無 完成清空該波所有怪後，額外獎勵給玩家的金幣。
groups (vector) 空 陣列不可為空 該波次所包含的 SpawnGroup 列表。會依序進行生成。

3. SpawnGroup (刷怪群組)

定義最細緻的生成設定，包含單一種類敵人的數量、刷怪頻率、特定起點以及血量/速度強化倍率。

屬性變數 (型態) 預設值 校驗規則 / 限制條件 功能說明
type (EnemyTypeId) Regular 須為合法的 EnemyTypeId 列舉 生成的敵人種類 (請參考第三節的敵人類型對照表)。
count (int) 0 必須大於 0 本組敵人的生成個數。
startDelay (float) 0.0F 必須大於或等於 0.0F 本組第一隻敵人開始生成的延遲時間（單位：秒，相對於波次倒數結束）。
interval (float) 1.0F 必須大於或等於 0.0F 組內敵人與敵人之間的生成間隔時間（單位：秒）。
spawnPointIndices (vector<int>) 空 索引值必須在合理的地圖起點數量內 核心機制：
1. 若為空陣列：敵人將會在所有起點同時生成一隻。
2. 若指定索引 (例如 {0} 或 {0, 2})：則會在指定的起點生成。
⚠️ 請注意：若指定多個索引，每次生成間隔會同時在所有指定起點各生成一隻敵人。
hpMultiplier (float) 1.0F 無 該組敵人的血量倍率 (一般為 1.0F，高於 1.0F 會更難擊殺)。
spdMultiplier (float) 1.0F 無 該組敵人的移動速度倍率 (一般為 1.0F，會影響實際格速)。

LevelConfig.hpp 標頭檔定義參考

以下為專案中 LevelConfig.hpp 的完整宣告與防呆校驗函式實作，開發時可對照參考變數型態與校驗邏輯：

#pragma once

#include <filesystem>
#include <sstream>
#include <stdexcept>
#include <string>
#include <unordered_set>
#include <vector>

#include "enemy/EnemyTypeConfig.hpp"

// -------------------- 刷怪群組配置 --------------------
struct SpawnGroup {
  EnemyTypeId type = EnemyTypeId::Regular; // 生成的敵人類型
  int count = 0;                           // 該組生成的敵人數量
  float startDelay = 0.0F;                 // 第一隻敵人的延遲生成時間（秒）
  float interval = 1.0F;                   // 敵人間隔生成時間（秒）
  std::vector<int> spawnPointIndices;      // 生成起點的索引列表（為空時在所有起點生成）
  
  float hpMultiplier  = 1.0F;              // 血量強化倍率（例如 1.2）
  float spdMultiplier = 1.0F;              // 速度強化倍率（例如 1.1）
};

// -------------------- 波次配置 --------------------
struct WaveConfig {
  int waveNumber = 1;             // 波次編號（用於 UI / 統計）
  bool isBossWave = false;        // 是否為 Boss 波次
  float prepTime = 3.0F;          // 該波開始前的準備倒數計時（秒）
  int clearRewardGold = 0;        // 清空此波怪物後的獎勵金幣
  std::vector<SpawnGroup> groups; // 該波包含的所有刷怪群組
};

// -------------------- 關卡配置 --------------------
struct LevelConfig {
  int levelNumber = 1;           // 關卡編號
  std::string mapPath;           // 地圖 CSV 檔案路徑
  int baseHp = 20;               // 基地初始生命值
  int startingGold = 150;        // 初始金幣
  std::vector<WaveConfig> waves; // 關卡的所有波次列表
};

extern const std::vector<LevelConfig> kLevelConfigs;

inline void validateLevelConfigs() {
  std::vector<std::string> errors;
  std::unordered_set<int> seenLevelNumbers;

  for (const LevelConfig &levelConfig : kLevelConfigs) {
    if (!seenLevelNumbers.insert(levelConfig.levelNumber).second) {
      errors.push_back("重複的關卡編號: " + std::to_string(levelConfig.levelNumber));
    }
    if (levelConfig.levelNumber <= 0) {
      errors.push_back("無效的關卡編號: " + std::to_string(levelConfig.levelNumber));
    }
    if (levelConfig.baseHp <= 0) {
      errors.push_back("關卡 " + std::to_string(levelConfig.levelNumber) + " 的 baseHp 必須大於 0");
    }
    if (levelConfig.mapPath.empty()) {
      errors.push_back("關卡 " + std::to_string(levelConfig.levelNumber) + " 未設定 mapPath");
    } else if (!std::filesystem::exists(levelConfig.mapPath)) {
      errors.push_back("關卡 " + std::to_string(levelConfig.levelNumber) + " 的地圖檔案不存在: " + levelConfig.mapPath);
    }
    if (levelConfig.waves.empty()) {
      errors.push_back("關卡 " + std::to_string(levelConfig.levelNumber) + " 沒有配置任何 wave");
    }

    for (const WaveConfig &waveConfig : levelConfig.waves) {
      if (waveConfig.waveNumber <= 0) {
        errors.push_back("關卡 " + std::to_string(levelConfig.levelNumber) + " 的無效 waveNumber: " + std::to_string(waveConfig.waveNumber));
      }
      if (waveConfig.prepTime < 0.0F) {
        errors.push_back("關卡 " + std::to_string(levelConfig.levelNumber) + " wave " + std::to_string(waveConfig.waveNumber) + " 的 prepTime 不能小於 0");
      }
      if (waveConfig.groups.empty()) {
        errors.push_back("關卡 " + std::to_string(levelConfig.levelNumber) + " wave " + std::to_string(waveConfig.waveNumber) + " 沒有配置 any spawn group");
      }

      for (const SpawnGroup &spawnGroup : waveConfig.groups) {
        if (spawnGroup.count <= 0) {
          errors.push_back("關卡 " + std::to_string(levelConfig.levelNumber) + " wave " + std::to_string(waveConfig.waveNumber) + " 的 group count 必須大於 0");
        }
        if (spawnGroup.startDelay < 0.0F) {
          errors.push_back("關卡 " + std::to_string(levelConfig.levelNumber) + " wave " + std::to_string(waveConfig.waveNumber) + " 的 group startDelay 不能小於 0");
        }
        if (spawnGroup.interval < 0.0F) {
          errors.push_back("關卡 " + std::to_string(levelConfig.levelNumber) + " wave " + std::to_string(waveConfig.waveNumber) + " 的 group interval 不能小於 0");
        }
      }
    }
  }

  if (!errors.empty()) {
    std::ostringstream oss;
    oss << "LevelConfig validation failed (" << errors.size() << "):";
    for (const std::string &error : errors) {
      oss << "\n - " << error;
    }
    throw std::runtime_error(oss.str());
  }
}
⚠️ 嚴格的防呆校驗機制 (validateLevelConfigs)
在遊戲啟動載入配置時，系統會自動對全域 kLevelConfigs 執行 validateLevelConfigs() 校驗。 若發生關卡 ID 重複、地圖檔案不存在、生命值 ≤ 0、無出怪波次、出怪時間/間隔 < 0、刷怪數量 ≤ 0 等情況， 系統將會主動拋出 runtime_error 導致程式崩潰。請務必在新增設定時遵循以上規則。

起點順序計算規則

起點索引的排序是由地圖引擎讀取 CSV 時所決定的。它嚴格遵循以下順序：

  1. 由下至上 (y 軸遞增)：從地圖的最底層 row (即 y = 0) 開始，掃描至最頂層。
  2. 由左至右 (x 軸遞增)：在同一列 (Row) 中，由最左側格往最右側格掃描。
  3. 累加標記：第一個掃描到的 Spawn 點為索引 0，第二個為 1，以此類推。
💡 索引範例說明：
如左圖所示，當地圖底部 (y=0) 無起點時，最先掃描到的是中間行 (y=1) 的左起點 (0,1) ➔ 標記為 Spawn 0； 接著掃描到右邊的起點 (4,1) ➔ 標記為 Spawn 1； 最後在頂部行 (y=3) 依序掃描到 (1,3) ➔ Spawn 2，與 (3,3) ➔ Spawn 3。

關卡定義實作

專案提供兩種主要的方式來建立波次資料：靜態結構宣告 與 動態程式碼生成。

方式 A：靜態初始化（適用於前中期波次少、規則固定）

利用 C++ 大括號 initializer list 直觀地寫死每一個波次。例如 Level 1 與 4：

// 宣告 Level 4
{
    LevelConfig lvl;
    lvl.levelNumber = 4;
    lvl.mapPath = "assets/maps/map_04.csv";
    lvl.baseHp = 100;
    lvl.startingGold = 200;
    lvl.waves = {
        // Wave 1: 延遲 0 秒派 10 隻普通怪，延遲 0 秒派 2 隻冰怪
        {1, false, 4.0F, 30, {
            {EnemyTypeId::Regular, 10, 0.00F, 1.00F, {}},
            {EnemyTypeId::Icy, 2, 0.0F, 1.0F, {}}
        }},
        // Wave 2
        {2, false, 4.0F, 30, {
            {EnemyTypeId::Regular, 12, 0.00F, 1.00F, {}}
        }}
    };
    configs.push_back(lvl);
}

方式 B：動態程式化生成（適用於後期怪量極大、具備規律公式的波次）

使用迴圈演算法在執行期（Run-time）將 SpawnGroup 推入 waves。以 Level 5 的 Wave 2 為例：

{
    WaveConfig w2;
    w2.waveNumber = 2;
    w2.isBossWave = false;
    w2.prepTime = 4.0F;
    w2.clearRewardGold = 30;

    // 敵人生成類型輪流表
    static const EnemyTypeId pattern[] = {
        EnemyTypeId::Regular, EnemyTypeId::Armored, EnemyTypeId::Healer, EnemyTypeId::Fast,
        EnemyTypeId::Regular, EnemyTypeId::Jet, EnemyTypeId::Fighter, EnemyTypeId::Fast,
        EnemyTypeId::Heli, EnemyTypeId::Jet, EnemyTypeId::Toxic, EnemyTypeId::Icy
    };

    // 程式化產生 300 組生成指令
    for (int i = 0; i < 300; ++i) {
        SpawnGroup g;
        g.type = pattern[i % 12];
        g.count = 1;
        g.startDelay = i * 0.1f; // 遞增延遲，實現一個接一個的刷怪效果
        g.interval = 1.0f;
        
        // 演算法計算決定出生點 (例如在 0~99 之間震盪折返)
        int subStep = i % 100;
        int spIdx = 0;
        if (subStep < 25) spIdx = subStep;
        else if (subStep < 50) spIdx = 26 + (subStep - 25) * 2;
        else if (subStep < 75) spIdx = 99 - (subStep - 50);
        else spIdx = 73 - (subStep - 75) * 2;
        
        g.spawnPointIndices = { spIdx };
        w2.groups.push_back(g);
    }
    lvl.waves.push_back(w2);
}
🔄 無限循環機制 (Endless Loop Mode)
除了 Level 1 以外，當關卡的所有波次被清空後，遊戲將會開啟無限循環模式：
  • 每開啟新的一輪，怪物屬性以指數級別強化：血量 × 1.2loopCount，速度 × 1.1loopCount。
  • 自第二關起，進入第 2 輪 (loopCount = 1) 時，遊戲介面會顯示前進下一關的快捷按鈕。
